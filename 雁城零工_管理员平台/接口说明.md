# 雁城零工接口与数据库说明

本平台采用“微信小程序/管理员页面 -> Node 接口服务 -> MySQL”的结构。前端不直接连接 MySQL，也不再把业务数据保存到浏览器。

## 数据库

SQL 文件：

```text
sql/yancheng_lingong.sql
```

数据库名：

```text
yancheng_lingong
```

核心表：

| 表名 | 用途 |
| --- | --- |
| admin_users | 管理员账号 |
| wx_users | 微信登录用户 |
| jobs | 岗位信息、发布状态、审核原因 |
| user_favorites | 用户收藏岗位 |
| applications | 用户投递记录和跟进状态 |

## 状态字段

岗位状态 `jobs.status`：

| 值 | 说明 |
| --- | --- |
| pending | 待审核 |
| published | 已发布，小程序可见 |
| rejected | 已驳回 |
| offline | 已下线 |

投递状态 `applications.status`：

| 值 | 说明 |
| --- | --- |
| new | 新投递 |
| contacted | 已联系 |
| hired | 已录用 |
| closed | 已关闭 |

## 小程序接口

### 1. 获取已发布岗位

`GET /api/jobs`

查询参数：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| keyword | string | 搜索岗位、公司、地点 |
| category | string | 岗位分类 |
| area | string | 工作区域 |
| salaryType | string | 结算方式 |
| page | number | 页码 |
| pageSize | number | 每页数量 |

返回示例：

```json
{
  "code": 0,
  "data": {
    "list": [
      {
        "id": 2,
        "title": "咖啡店晚班店员",
        "category": "餐饮服务",
        "salary": "20元/小时",
        "salaryType": "周结",
        "headcount": 2,
        "displayLocation": "蒸湘区",
        "location": "蒸湘区船山大道万达附近",
        "company": "青屿咖啡",
        "contact": "李店长",
        "phone": "13800138002",
        "workTime": "18:00-22:30",
        "description": "负责点单、出品辅助、桌面整理，有餐饮经验优先。",
        "status": "published",
        "createdAt": "2026-05-25 14:05"
      }
    ],
    "total": 1
  }
}
```

### 2. 小程序发布岗位

`POST /api/wechat/jobs`

小程序“发布”页面调用。提交后写入 MySQL 的 `jobs` 表，默认状态为 `pending`，不会立即展示在“找零工”列表。管理员在后台“岗位审核”通过后，状态变为 `published`，小程序 `GET /api/jobs` 才会返回该岗位。

请求示例：

```json
{
  "title": "展会协助",
  "category": "促销导购",
  "salary": "180元/天",
  "salaryType": "日结",
  "headcount": 3,
  "displayLocation": "雁峰区",
  "location": "雁峰区先锋路商圈",
  "company": "张先生发布",
  "contact": "张先生",
  "phone": "13900139001",
  "workTime": "9:00-18:00",
  "description": "负责现场引导和物料整理。"
}
```

### 3. 微信登录用户同步

`POST /api/auth/wechat-login`

小程序端通过 `wx.login` 获取 `code` 后，把用户资料提交给后端。真实上线时，后端应使用 `appid`、`secret` 和 `code` 换取 `openid`；当前示例服务为了便于调试，允许传入 `openid` 或 `code` 作为演示标识。

请求示例：

```json
{
  "code": "wx_login_code",
  "openid": "wx_openid_demo_001",
  "nickname": "一米阳光",
  "avatarUrl": "https://example.com/avatar.png",
  "phone": "13900139001",
  "city": "衡阳"
}
```

### 4. 提交岗位投递

`POST /api/applications`

请求字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| jobId | number | 是 | 岗位 ID |
| userId | number | 是 | 用户 ID |
| userName | string | 是 | 用户昵称或姓名 |
| phone | string | 是 | 联系电话 |
| wxAvatarUrl | string | 否 | 微信头像 |
| note | string | 否 | 用户备注 |

请求示例：

```json
{
  "jobId": 2,
  "userId": 1,
  "userName": "一米阳光",
  "phone": "13900139001",
  "wxAvatarUrl": "https://example.com/avatar.png",
  "note": "可连续做一周"
}
```

## 管理员接口

管理员接口需要先登录。登录成功后，服务端会写入 `HttpOnly` Cookie：`yc_admin_session`。

### 0. 管理员登录

`POST /api/admin/login`

请求示例：

```json
{
  "username": "admin",
  "password": "admin123"
}
```

退出登录：

`POST /api/admin/logout`

### 1. 管理端岗位列表

`GET /api/admin/jobs`

查询参数：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| keyword | string | 搜索岗位、公司、联系人、地点 |
| status | string | all/pending/published/rejected/offline |

### 2. 发布岗位

`POST /api/jobs`

新增岗位写入 MySQL 的 `jobs` 表，默认状态为 `pending`。

请求字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| title | string | 是 | 职位名称 |
| category | string | 是 | 职位类型 |
| salary | string | 是 | 薪资待遇 |
| salaryType | string | 是 | 结算方式 |
| headcount | number | 是 | 招聘人数 |
| displayLocation | string | 是 | 展示区域 |
| location | string | 是 | 详细地址 |
| company | string | 否 | 发布单位 |
| contact | string | 是 | 联系人 |
| phone | string | 是 | 联系电话 |
| workTime | string | 否 | 工作时间 |
| description | string | 否 | 职位描述 |

### 3. 审核岗位

`PATCH /api/admin/jobs/{id}/review`

请求示例：

```json
{
  "status": "published",
  "reviewReason": "",
  "reviewerId": 1
}
```

### 4. 管理端用户列表

`GET /api/admin/users`

读取 `wx_users` 表，同时统计收藏数量和投递数量。

### 5. 管理端投递列表

`GET /api/admin/applications`

查询参数：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| keyword | string | 搜索用户、手机号、岗位 |
| status | string | all/new/contacted/hired/closed |

### 6. 更新投递状态

`PATCH /api/admin/applications/{id}/status`

请求示例：

```json
{
  "status": "contacted"
}
```

### 7. 导出后台数据

`GET /api/admin/export`

从 MySQL 查询岗位、用户、投递记录并返回 JSON，用于管理员平台导出。
